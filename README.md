# K230 双线循迹小车

2026 年电赛基础题的练手车。赛道是两条平行的黑线，车要沿着两线中间跑，同时识别赛道上的转向标识、红绿灯、路障和终点。

整份代码跑在 CanMV K230 上，用 Python 写。摄像头取图后做两件事：一边用灰度阈值找左右两条黑线的位置，算出车相对赛道中线的横向偏差；一边跑一个 AnchorBaseDet 检测模型，认出 left / right / red / green / yellow / destination / roadblock 七类目标。两路结果打包成 8 字节的串口帧发给下位机，转向和速度是下位机在调。

## 硬件

- 主控：CanMV K230，HDMI 输出（lt9611）接显示器调试
- 摄像头：RGB888P，1280×720 取流，巡线按 640×480 的坐标基准折算
- 外设：串口 115200 接驱动板，板载蜂鸣器做障碍物提示
- 依赖：`libs.PlatTasks`、`libs.PipeLine`、`libs.Utils` 来自 CanMV 固件，`ybUtils.YbUart`、`ybUtils.YbBuzzer` 来自亚博智能的开发包

## 巡线怎么算的

灰度用 `(R + 2G + B) / 4` 近似，阈值 50 以下算黑。左右两个 ROI 各自在三条扫描线上找最长的黑色连续段，取段中点按权重合成一个横向位置。没找到线就返回空。

拿到左线位置 `left_x` 和右线位置 `right_x` 之后：

- 两条都找到，中线取 `(left_x + right_x) / 2`
- 只找到一条，用固定的线间距 `LINE_SPACE = 377` 补出另一条，再算虚拟中线

中线减屏幕中心就是偏差 `E`。`E` 出来之后还要过三道：乘 0.25 缩放、按 0.2 做一阶滤波、单帧变化不超过 4 个像素。下位机拿到的就是滤波后的值。

丢线有一套兜底。刚丢的前 5 帧继续沿用上一次的 `E`，再往后如果还是没线，就把最近 10 帧的偏差做加权拟合（越新的权重越大）顶上去，最多顶 50 帧，超了就归零。

## 转弯和识别

转向指令不是每帧都发，靠状态机撑一段时间：

- 一侧边线从"有"变成"没有"，同时画面里没有横向线，就按丢的是哪一侧决定左转还是右转，维持 10 帧
- 如果有横向线（路口），也按丢线侧判断
- 模型给出 left / right 时优先级最高，直接覆盖

其他几类只做标志位：红灯 1、黄灯 2、绿灯 3，检测到 roadblock 就让蜂鸣器以 80ms 的间隔持续响，检测到 destination 置终点位。

## 串口帧

8 字节，帧头 0x23，最后一字节是前 7 字节的累加和。

| 字节 | 含义 |
| --- | --- |
| 0 | 0x23 帧头 |
| 1 | 方向：0 直行 / 1 左 / 2 右 |
| 2 | 灯：0 无 / 1 红 / 2 黄 / 3 绿 |
| 3 | 障碍物：0 无 / 1 有 |
| 4 | 终点：0 否 / 1 是 |
| 5 | 偏差 E，有符号，-128 ~ 127 |
| 6 | 丢线标志：1 表示有一侧没找到（999） |
| 7 | 校验和 |

## 怎么跑

1. 把 `model/` 下的 kmodel 和 `deploy_config.json` 一起拷到板子的 `/sdcard/mp_deployment_source/`，文件名别改，`deploy_config.json` 里的 `kmodel_path` 是按文件名找的
2. `src/main.py` 用 CanMV IDE 打开，连上板子直接运行
3. 调参的位置都集中在文件开头，`BLACK_GRAY_THRESHOLD`、`LINE_SPACE`、`ERROR_MAX_STEP` 这几个最常动

想单独验证模型的话，`src/examples/` 里的脚本能直接跑单张图和视频。

## 关于这份仓库

原始工程目录里有 8 个几乎重复的迭代文件夹，每个都塞了一份 110 张的抓拍图和一份 kmodel，加起来 150M 左右。这里只留了代码、两个关键模型和几张样图，抓拍图和重复的模型没传。`cammv/`（K230 烧录工具）和 `test/`（一堆跟车无关的 C 语言练习题）也剔掉了。
